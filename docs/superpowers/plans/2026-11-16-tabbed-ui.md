# Tabbed UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three Figma screens (Employee Dashboard, Mini Dashboard, Profile Card) in a React + TS + Tailwind app, switchable by tabs.

**Architecture:** `App` holds `activeTab` state and renders a `TabBar` plus the selected page. Pages compose shared prop-driven components. Theme tokens live in `@theme` in `src/index.css`.

**Tech Stack:** Vite 8, React 19, TypeScript, Tailwind CSS v4 (`tailwindcss`, `@tailwindcss/vite`), Inter font.

**Spec:** `docs/superpowers/specs/2026-11-16-tabbed-ui-design.md`

## Global Constraints

- Tailwind v4 via `@tailwindcss/vite` plugin; theme in `@theme` in `src/index.css`, no `tailwind.config.js`.
- No router, no state library, no icon library (inline SVG).
- Primary navy is `#234e70`. Other colors are eyeballed from screenshots; user will refine later, so keep every color a theme token (never raw hex in components).
- Font: Inter.
- Flexbox and Grid used for layout; all pages responsive (sidebar collapses on small screens).
- Verification is `npm run lint`, `npm run build`, and a visual check in `npm run dev` (no test framework in scope).

## Review Focus

- Empty/long text: very long employee names or emails truncate instead of breaking layout.
- Narrow viewport (~375px): no horizontal page scroll; table scrolls inside its card.
- Rapid tab switching: each page renders correctly from a fresh mount.
- Unknown status/variant value: `StatusBadge` and `Button` fall back to a default variant (enforced by TS union types).
- Avatar with a single-word or empty name: initials don't crash.
